# X1 — Prioridad de narración: código → Groq → IA local
- Orden fijo: 1) narrador por código (siempre primero; si entiende, nadie más interviene). 2) Groq, si hay clave. 3) IA local, si está lista: cuando no hay clave O cuando Groq falla (error de red, cupo/límite de tokens agotado —429, rate limit, cuota diaria—, tiempo agotado, salida rechazada por el validador). Tras un límite de tokens, saltar Groq directo a local hasta que pase el período de espera indicado por la API (o 10 min si no lo indica). 4) Plantilla.
- Un solo punto de decisión en narrador/index.js (bloque TIPOS_TURNO.IA); cada nivel devuelve la misma forma. La clave de Groq nunca llega a la IA local.
- Registro: sin campos nuevos; motivo de caída anotado en `errores` existente.
- Tests: código entiende → ni Groq ni local; Groq ok → no local; Groq falla → local; Groq falla y local no lista → plantilla; sin clave → local; ambas fallan → plantilla; eco rechazado en Groq → local.
- Silencioso: el jugador nunca ve avisos de tokens, cupo, errores de API ni qué nivel respondió; el cambio de Groq a local es invisible. Solo el panel de prueba (modo debug) muestra el nivel y el motivo.
- Tests extra: 429 → local sin texto de aviso; durante la espera no se llama a Groq; pasada la espera vuelve a Groq.
